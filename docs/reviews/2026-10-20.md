The boundary portfolio initially produced 28 failures; the archive portfolio
produced 14; the artifact portfolio produced 13; the record/documentation
portfolio produced 7. These counts describe executed reproductions, not final
test totals. Cases already rejected by the old implementation were retained as
controls, not labelled newly reproduced defects.

Baseline failures were version disagreement, unrecognized existing DOI strings,
and a fallback-root test that assumed temporary directories had no enclosing
`pyproject.toml`. Versions are synchronized for release, DOI strings were checked
against real Zenodo records, and the fallback test now uses an absent path with
no source-file write. No failure was skipped or threshold lowered.

Cross-repository findings: consumers need strict instrument-envelope validation
separate from correspondence, envelope-driven order restoration for sorted
native JSON, and separate custody of intake/evidence sidecars. No sibling
implementation was edited or dynamically certified by this release. External
history anchoring, if wanted, belongs to a separate Witness Register contract.

The release packet maps these dispositions to implementation commits and final
gate receipts. Daniel retains the new Zenodo DOI reserve/mint step.

Rendered checks additionally exposed the inherited unbreakable envelope tuple
and incorrect source image links after the manuscript's move under `docs/`.
The tuple now has explicit break opportunities; image links and the folder
instruction use the correct root-relative traversal. A local image-reference
test prevents the source-provenance failure from recurring. The first external
validation attempt stalled in Git-ignore pipe I/O and was terminated; its log
is retained as a nonpassing attempt, followed by a fresh validation run.
